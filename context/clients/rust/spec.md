# Rust Client — Spec

Specifies the composition of the Rust client (`rust/`). Builds on
[requirements.md](./requirements.md); part mechanics live in the child specs.

## Status

Draft.

**Maturity: experimental**

## Scope

| Child | Owns | Crates |
| --- | --- | --- |
| [`01-schema`](./01-schema/spec.md) | schema DSL, DDL, client documents, events, materializers, query builder, schema hashes | `livestore-schema`, `livestore-core` |
| [`02-sqlite`](./02-sqlite/spec.md) | the SQLite build and leader persistence (eventlog, state, rollback, rebuild) | `livestore-sqlite-sys`, `livestore-sqlite` |
| [`03-leader`](./03-leader/spec.md) | leader sync processor, syncstate merge, backend contract | `livestore-sync`, `livestore-core` |
| [`04-sync-cf`](./04-sync-cf/spec.md) | sync-cf provider client (WebSocket, HTTP) | `livestore-sync-cf` |
| [`05-store`](./05-store/spec.md) | client session, store, reactivity, in-process adapter | `livestore` |

`livestore-todomvc` (example schema) and `todo-tui` (the `todo` CLI) consume the
stack and own no contract.

Dependency direction:

```text
livestore-core <- livestore-schema <- livestore-sqlite <- livestore-sync <- livestore-sync-cf
                                                                      ^
                                                                      +--- livestore (store)
livestore-sqlite-sys: linked by rusqlite in place of libsqlite3-sys
```

## Mapping From Effect

Each Effect concept maps onto one Rust mechanism so ported tests stay readable
next to their TypeScript originals: services and layers become trait objects
handed to a builder, tagged errors become `thiserror` types whose `tag()` returns
the TS `_tag`, scopes and fibers become cancellation tokens and tokio tasks,
`SubscriptionRef` becomes `tokio::sync::watch`, `TestClock` becomes paused tokio
time. The full table and the test-control mapping are in
[`contributor-docs/rust/effect-to-rust.md`](../../../contributor-docs/rust/effect-to-rust.md).

## Verification

- `devenv tasks run check:rust` runs check, clippy, the unit/fixture suites, and
  the live suite against the pinned core's sync-cf worker
  (`rust/scripts/test-live.sh`). CI: `.github/workflows/rust.yml`, only on
  changes to `rust/`, devenv files, or the megarepo pin.
- Parity: `rust/parity/parity.md`, generated by `rust/scripts/gen-parity.py` from
  core's `vitest list` and `rust/parity/status/*.tsv`. It records the core commit
  it was generated at (LSC.CLIENT.RUST-R05). Regeneration is described in
  [`rust/README.md`](../../../rust/README.md#parity-with-the-typescript-tests).
